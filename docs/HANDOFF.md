# 뱀서라이크 전환 — 인수인계

작성: 2026-07-18 (자동 구현 세션)

## 한 줄 요약

횡스크롤 프로토타입을 탑다운 뱀서라이크 **강사용 정답본**으로 전환 완료.
스크립트 18종 + 프리팹 5종 + 데이터 에셋 9종 + 씬 배선까지 코드로 구성했고,
**Unity 배치 모드 컴파일과 에디터 스크립트 실행으로 검증**했다.

## ⚠️ 가장 중요한 한계 — 반드시 읽을 것

**나는 에디터를 열어 플레이(Play 모드)해보지 못했다.** 이 환경에서 Unity 테스트 러너가
프로젝트 경로의 한글(`2026 SW중심대학 활동`) 때문에 무한 루프에 빠져 실행되지 않는다
(자세한 내용은 `docs/superpowers/plans/2026-07-17-vampire-survivors.md` Task 0).

그래서 내가 **검증한 것**과 **못 한 것**을 구분한다.

**검증됨 (배치 모드로 확인):**
- 18개 스크립트 전부 컴파일 통과 (`error CS` 0건)
- 프리팹 5종이 올바른 컴포넌트·태그·트리거·상호 참조로 생성됨 (YAML 확인)
- 씬의 모든 참조가 연결됨 — 빈 참조 0, 필드 누락 경고 0 (YAML 확인)
- 데이터 에셋 9종 생성, 리스트에 정확한 개수로 배선됨

**검증 안 됨 (반드시 사람이 에디터에서 확인):**
- 게임이 실제로 재밌게/정상적으로 도는가
- UI가 화면에 제대로 보이고 겹치지 않는가
- 플레이어가 움직이고, 총알이 자동으로 나가고, 레벨업 카드가 뜨고 클릭되는가
- 몬스터 3종이 시간에 맞춰 등장하는가

**돌아오면 첫 할 일: Unity에서 TestScene 열고 Play 눌러보기.** 아래 체크리스트 참조.

## 돌아와서 할 검증 체크리스트

Unity 에디터에서 `Assets/Scenes/TestScene.unity`를 열고 Play:

1. [ ] 방향키로 플레이어가 8방향 이동하는가 (중력으로 떨어지지 않는가)
2. [ ] 잠시 기다리면 화면 밖에서 몬스터가 몰려오는가
3. [ ] 스페이스바를 안 눌러도 총알이 가장 가까운 몬스터로 자동 발사되는가
4. [ ] 몬스터가 총에 맞아 죽고 젬을 떨구는가
5. [ ] 젬이 플레이어 근처에서 빨려오는가
6. [ ] 젬을 모으면 레벨업하며 게임이 멈추고 강화 카드 3장이 뜨는가
7. [ ] 카드를 클릭하면 능력치가 오르고 게임이 재개되는가
8. [ ] 몬스터에 닿으면 체력바가 줄고, 0이 되면 게임오버 패널이 뜨는가
9. [ ] 상단 UI(타이머·체력바·경험치바·레벨)가 겹치지 않고 보이는가
10. [ ] 30초/60초에 사격형·폭발형 몬스터가 등장하는가

문제가 나면 대부분 **인스펙터 참조 누락**이 아니라 **런타임 로직/수치** 문제일 것이다
(참조는 YAML로 검증했으므로). 콘솔의 NullReference를 먼저 확인.

## 알려진 위험 지점 (내가 blind로 만든 것들)

1. **UI 위치·크기** — 체력바·경험치바·레벨텍스트를 좌상단에, 타이머를 상단 중앙에,
   강화 카드를 화면 중앙에 코드로 배치했다. 화면 해상도에 따라 위치가 어색할 수 있다.
   눈으로 보고 조정 필요.
2. **강화 카드 디자인** — 기능 위주의 평범한 회색 카드다. 아이콘도 비어 있다
   (UpgradeData의 icon 필드에 스프라이트를 넣으면 표시됨). 수업 전 꾸미면 좋다.
3. **몬스터/젬/총알 스프라이트** — 전부 기존 Monster 스프라이트를 색만 바꿔 쓴다.
   더 나은 스프라이트로 교체하면 보기 좋다 (MonsterData.sprite, 프리팹의 SpriteRenderer).
4. **수치 밸런스** — 강화 수치, 경험치 곡선, 몬스터 능력치는 임시값이다.
   플레이하며 조정해야 한다 (`Assets/Data/` 의 에셋들, 인스펙터에서 바로 수정).

## 학생 빈칸 7개 (메서드 단위 클론코딩)

학생이 직접 타이핑할 자리는 코드에 `// ─── 학생 빈칸 N (M일차) ───`로 표시돼 있다.

| 빈칸 | 파일 | 메서드 | 일차 | 개념 |
|---|---|---|---|---|
| 1 | `PlayerController.cs` | `Move()` | 1일차 | 벡터, normalized |
| 2 | `ChaseBehaviour.cs` | `Chase()` | 1일차 | 방향 벡터 재활용 |
| 3 | `AutoAttack.cs` | `FindNearestMonster()` | 2일차 | 배열 순회 최솟값 |
| 4 | `PlayerHealth.cs` | `TakeDamage()` | 2일차 | 쿨타임/무적시간 |
| 5 | `ExpGem.cs` | `Update()` 마그넷 | 3일차 | MoveTowards, 거리 |
| 6 | `PlayerLevel.cs` | `AddExp()` | 3일차 | 누적, 임계값 |
| 7 | `UpgradeManager.cs` | `ApplyUpgrade()` | 3일차 | switch, timeScale |

### 학생 배포본 만드는 법 (아직 안 만듦 — 후속 작업)

현재는 **정답본**이다. 학생 배포본은 위 7개 메서드의 본문만 비운 버전이다.
표식 주석(`학생 빈칸 N`) 사이의 코드를 지우고 `// TODO: 여기를 채우세요`로 바꾸면 된다.
단, **빈칸을 비워도 컴파일은 되어야 한다** (1일차에 학생이 열자마자 에러나면 안 됨).
그래서 단순 삭제가 아니라 스텁이 필요하다. 예:
- `Move()` → 본문 비움 (void라 OK)
- `FindNearestMonster()` → `return null;` 만 남김
- `AddExp()` → 본문 비움

이 작업은 자동화 스크립트로 만들 수 있으나 이번 세션에선 안 했다. 정답본이 먼저다.

## 디자인 패턴 (배포본 인프라에만, 학생은 결과만 사용)

- **싱글톤** — `GameManager`, `PoolManager` 딱 2개. 남용 금지 원칙.
- **오브젝트 풀링** — `PoolManager`. 몬스터·총알·젬 재사용. 이중 반납 방지 포함.
  3일차 시연용 토글(`poolingEnabled`)이 있다 — 끄고 후반부 렉을 체감시킨 뒤 켠다.
- **심플 팩토리** — `MonsterFactory`. behaviorType으로 프리팹 선택.
  (GoF 팩토리 메서드가 아님 — 이유는 설계 문서 결정4 참조. 수업 중 이름 정확히 쓸 것.)

## 몬스터 행동 3종

| 행동 | 등장 | 특징 |
|---|---|---|
| `ChaseBehaviour` | 0초~ | 직선 추적 |
| `ShooterBehaviour` | 30초~ | 사거리 밖 접근, 안에서 멈춰 발사 |
| `ExploderBehaviour` | 60초~ | 죽을 때 범위 폭발 |

새 몬스터를 만들려면 `Assets/Data/Monsters/`의 `.asset`을 복제해 색·크기·수치·behaviorType만
바꾸면 된다. 프리팹은 건드릴 필요 없다. (3일차 학생 활동)

## 재실행 가능한 셋업 스크립트

`Assets/Editor/`에 있고 Unity 메뉴 **[뱀서라이크]**에 뜬다:
- `1. 에셋·프리팹 생성` — 데이터·프리팹 재생성 (덮어씀, 안전)
- `2. 씬 배선` — ⚠️ UI를 새로 만들므로 재실행하면 **UI가 중복 생성됨**. 한 번만 실행.
- `3. 타이머 위치 보정` — 일회성 UI 위치 조정

수업용으로 프로젝트를 한글 없는 경로(예: `C:\Dev\GwangmunHigh`)로 옮기면
테스트 러너도 살아나고 여러 문제가 예방된다. 권장.
